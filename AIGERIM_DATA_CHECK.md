Проверка данных SPHEREx для Barnard's Star (GJ 699)
Дата проверки: 14 ноября 2026 года.
Целевой объект проекта: Barnard's Star (звезда Барнарда), Gaia DR3 source_id 4472832130942575872.
Важно не путать Barnard's Star со звездой/галактикой Barnard's Galaxy — NGC 6822. Это разные объекты. Для текущей демонстрации SPHEREx используем именно Barnard's Star (GJ 699).

1. Главный результат
Первоначальная таблица tables/spectral-images.tbl не содержит подходящих наблюдений Barnard's Star. Её координатные границы относятся к другой области неба — полю NGC 6822 (Barnard's Galaxy). Поэтому эту таблицу нельзя использовать как набор кадров звезды Барнарда.

Для Barnard's Star выполнен отдельный запрос к архиву NASA/IPAC IRSA SIA по координатам Gaia DR3 с учётом собственного движения. Запрос вернул 378 кандидатов; 358 предсказанных положений звезды попадают внутрь footprint кадров с запасом более 10 угловых секунд. Из этой выборки отобраны три наблюдения SPHEREx одного детектора D1 и выпуска DR1 для начальной проверки.

Ограничение текущего результата: для выбранных трёх наблюдений сохранены метаданные и заголовки FITS, но сами FITS-изображения ещё не загружены в репозиторий и не проверены по пикселям. Поэтому пока нельзя утверждать, что звезда уже обнаружена на снимках или что её движение измерено по данным SPHEREx.

Ближайший центр кадра исходной таблицы находится примерно в 30.6603° от Barnard's Star. Максимальное расстояние от центра кадра до его угла среди записей таблицы — около 2.5406°. Следовательно, ни один из этих кадров не покрывает звезду Барнарда.

При этом координаты 370 из 372 footprint-ов включают центр NGC 6822; два оставшихся кадра проходят примерно в 22″ от него. Это указывает на область Barnard's Galaxy, но не доказывает, какое имя или координаты вводились в исходном запросе: поле confirmed_target в selection.json равно null.

Вывод: первоначальная таблица полезна как диагностический пример неверного для нашей цели поля, но она не является источником тестовых кадров Barnard's Star. Для проекта используем отдельную выборку IRSA из следующего раздела.

5. Три выбранных наблюдения для первого теста
Для первичной проверки выбраны три наблюдения одного детектора D1 и одного выпуска DR1, взятые на разных датах. В каждой выбранной записи использованы точные MJD-AVG и DATE-AVG из расширения FITS IMAGE.
obs_id	Среднее время UTC (DATE-AVG)	MJD-AVG UTC	Детектор / выпуск	Запас до края footprint
2025W35_1A_0432_4	2025-08-27 05:07:00.174	60914.213196455	D1 / DR1	533.25″
2025W40_1A_0471_1	2025-10-01 03:08:33.664	60949.130945182	D1 / DR1	2336.70″
2026W11_1A_0539_2	2026-03-11 13:36:50.027	61110.567245680	D1 / DR1	4944.66″


Для всех трёх записей по сохранённым заголовкам проверено:
- TIMESYS=UTC;
- RADESYS=ICRS;
- DETECTOR=1;
- размер массива IMAGE — 2040 × 2040 пикселей;
- DATE-AVG согласуется с MJD-AVG в пределах 1 ms;
- предсказанная позиция Barnard's Star находится внутри footprint и внутри изображения по WCS.
Важно для анализа: один и тот же детектор D1 не гарантирует одну и ту же эффективную длину волны. SPHEREx использует линейно-переменный фильтр; спектральное значение зависит от положения на детекторе. Перед сравнением яркости кадров нужно получать длину волны в позиции цели для каждого наблюдения и отбирать сопоставимые спектральные интервалы.
6. Предсказанные координаты и ожидаемое смещение
Положение звезды на моменты выбранных наблюдений рассчитано существующим скриптом barnard_motion.py и сохранено в [`output/barnard_positions_irsa.csv`](output/barnard_positions_irsa.csv).
obs_id	RA ICRS (°)	Dec ICRS (°)
2025W35_1A_0432_4	269.446344534180	+4.767221894312
2025W40_1A_0471_1	269.446323148246	+4.767497402397
2026W11_1A_0539_2	269.446224270495	+4.768771209715


Между первым и последним наблюдениями прошло 196.354049 дня. В используемой модели ожидаемое смещение составляет 5.594198″. При указанном в таблице масштабе пикселя SPHEREx 6.15″/pixel это примерно 0.91 пикселя.

Это важная оговорка для демонстрации: на трёх выбранных датах движение может быть слишком небольшим, чтобы убедительно показать его простым миганием кадров. Для подтверждения понадобится точная регистрация изображений и измерение центроида, а не только визуальное сравнение.

В расчёте установлено parallax_applied=false. Характерный масштаб годичного параллакса для Barnard's Star — около 0.547″. Формальные ошибки координат Gaia (порядка 0.3–0.4 mas) не включают ошибку астрометрической привязки SPHEREx, ошибку центроида, неприменённый параллакс и возможные систематики обработки. Поэтому формальные ошибки нельзя представлять как полную точность измерения на снимках.

Это предсказание движения по Gaia, а не измерение движения по SPHEREx. Измеренный собственный ход можно указывать только после загрузки самих изображений, регистрации кадров и измерения положений звезды.

8. Статус FITS и runtime-кэша
В текущем архиве репозитория:
- папки cache/ нет;
- полные FITS-файлы трёх выбранных наблюдений в репозитории не сохранены;
- сохранены прямые FITS-ссылки, VOTable с результатом поиска, JSON с метаданными и текстовые заголовки IMAGE;
- PNG-кадры, PNG-маски флагов и result.json для выбранной тройки не сохранены.
Папка cache/ указана в .gitignore. Код api/cache.py использует её как runtime-хранилище (либо использует путь из CACHE_DIR). api/irsa.py и api/jobs.py сохраняют туда промежуточные и обработанные данные при фактическом выполнении задач.

При старте api/main.py по умолчанию запускает jobs.prewarm() в отдельном фоновом потоке, если PREWARM не равен 0. Функция prewarm() отправляет запросы для пяти встроенных целей в режиме coadd. Это только запуск фоновых задач: он не подтверждает, что загрузка и обработка завершились успешно.

Есть ещё одно несоответствие, важное именно для этой проверки: встроенный пресет barnard в api/resolve.py настроен на детектор D3, тогда как три выбранных здесь наблюдения — D1 / DR1. Поэтому стандартный prewarm() для barnard не создаёт автоматически кэш именно для этой тройки D1. Для демонстрации нужно отдельно настроить запрос на D1 и убедиться, что все выбранные FITS скачаны, обработаны и результаты реально появились в постоянном runtime-хранилище.

Итог по кэшу: на дату проверки нельзя утверждать, что демонстрационный кэш Barnard's Star готов. Сначала необходимо скачать три выбранных FITS, проверить IMAGE, FLAGS, VARIANCE, ZODI и спектральную привязку, выполнить обработку, сохранить PNG/JSON и проверить повторное открытие после перезапуска сервера. Саму runtime-папку cache/ обычно не добавляют в GitHub; для хостинга нужно обеспечить постоянное хранилище.
